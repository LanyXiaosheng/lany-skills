# Lany Cover

为 Lany 小生生成长期一致的个人 IP 封面。这里的视觉身份已经定稿，不再询问或轮换风格。

## 开始前

1. 读取 `references/brand-system.md`。
2. 读取 `references/cover-workflow.md`。
3. 调用生图前读取 `references/imagegen-reliability.md`。
4. 角色参考按优先级使用：用户本次明确确认的头像 > `assets/lany-avatar-reference.png` > `assets/lany-character-reference-lite.png`。用户确认的头像是身份真源，不得被旧角色模板覆盖。

## 默认规则

- 当前任务属于 X 内容时，默认画幅 `5:2`；X 主页横幅用 `3:1` 并保留头像安全区。
- 公众号封面默认 `2.35:1`，小红书默认 `3:4`，正文头图默认 `16:9`。
- 用户已给平台、比例或尺寸时直接执行，不重复确认。
- 用户只给文章且上下文无法判断平台时，只询问平台这一项。
- 默认实际生成一张最终图；只有用户明确说“仅提示词”时才停止在提示词文件。

## 路径解析

- 用户给出的文章或输出路径优先。
- 其次使用用户附件或当前明确提到的 Markdown；当前目录只有一个候选 Markdown 时才能自动选择，存在多个候选时询问具体文件。
- 有本地文章时，以文章所在目录作为项目根；没有文章文件时，以当前可写工作目录作为项目根。
- 不根据模糊的“当前 md”扫描多个项目后猜文件。

## 工作流

1. 完整读取文章或主题，提炼短主标题、可选副标题、受众、一个主体和一个视觉隐喻。
2. 只使用品牌规范中的一种视觉系统，不展示风格菜单，也不混入第二种媒介。
3. 主标题最多两行，画面只保留一个主体关系。辅助文案最多两层。
4. 把最终提示词保存到 `<project-root>/lany-assets/lany-cover/<slug>/prompts/cover.md`。
5. 先运行可靠性预检，再调用内置 `image_gen`。输入参考图最多一张，提示词保持紧凑。
6. 将当前调用明确返回的图片先复制为 `cover-source.png`，检查人物身份、主色、媒介、标题、白底占比和实际尺寸。
7. X 长文最终 `cover.png` 必须是精确 `5:2`，默认 `1500×600`。源图比例不符时，只有主体和文字都在安全区才可运行 `scripts/finalize_ratio.py` 生成正式文件；否则重新生成。始终保留源图。
8. 用 `scripts/validate_output.py` 验证正式文件。验证失败的文件不得命名为 `cover.png`，也不得交付为最终封面。已有正式文件时使用 `cover-v2.png`、`cover-v3.png`。

## 角色与视觉约束

- 用户确认的头像是最高优先级身份真源。锁定头像中实际可见的脸型、发型、护目镜、耳机、服装轮廓、年龄感和像素媒介；不得因为旧参考图而换脸或增加明显配饰。
- 头像中不可见的细节不强制补齐。白色 `小生` 字标和蓝色闪电只有在参考图可见或用户明确要求时保留，不能与头像事实冲突。
- 封面固定使用“咨询报告视觉”：非对称编辑构图、大面积留白、证据/判断式视觉隐喻、细线网格或几何切面、清晰的信息层级；每张封面只保留一个核心主体关系，不强制加入流程图、节点链或密集卡片。
- `#D8FF00` 是唯一大面积高饱和强调色，背景以 `#0A0A0A` 和石墨灰为主，少量 `#F3F3ED`；蓝色只在角色或语义确有依据时使用。
- 人物保持参考图的精致像素插画和可见像素边缘；禁止平滑 3D 公仔、黏土、写实真人、日漫重绘和陌生脸。
- 禁止闲鱼黄、蓝紫霓虹、粉紫渐变、彩虹色、玻璃拟态、游戏 HUD、PPT、密集仪表盘、随机文字、乱码、水印和二维码。

## 交付

报告提示词、最终图片的绝对路径、使用的参考图和验证结果。图片已经生成但无法复制时，如实返回工具给出的实际路径。
