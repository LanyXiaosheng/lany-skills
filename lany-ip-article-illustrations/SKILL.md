# Lany IP Article Illustrations

为 Lany 小生的长文生成同一套个人 IP 正文插图。角色、颜色和媒介已经确认；不要再次要求选角色或选风格。

## 开始前

1. 读取 `references/brand-system.md`。
2. 读取 `references/character-spec.md`。
3. 读取 `references/article-workflow.md`。
4. 调用生图前读取 `references/imagegen-reliability.md`。
5. 角色参考按优先级使用：用户明确确认的头像或角色图 > `assets/lany-avatar-reference.png` > `assets/lany-character-reference-lite.png`；只有多角度身份确实必要时才使用角色设定板。

## 工作流

1. 完整读取文章，不根据标题或节选猜内容。
2. 根据认知密度自动决定 1—8 张图，并为每张选择 `流程拆解` 或 `核心动作`。数字和精确比较优先交给 `$lany-data-charts`；关系图、概念图优先交给 `$lany-infographics`。用户明确要小生插画时遵从其要求。
3. 每张图只承担一个理解任务：一个判断、机制、转折、工作流或可交付结果。
4. 所有图片固定为 16:9，默认使用“头像中的像素小生 + 白色背景上的咨询报告视觉”。只有用户明确要求透明背景或黑色/深色背景时，才切换到对应模式；背景模式不改变角色、构图关系或品牌色。禁止在同一篇文章里切换 3D、写实、黏土、平滑日漫或其他人物媒介。
5. 把插图计划和紧凑提示词保存到 `<article-dir>/.lany-ip-assets/illustrations/<article-slug>/illustration-plan.md` 与 `prompts/`。
6. 先做网络预检，再逐张调用内置 `image_gen`。一张图一次调用，成功后立即复制为 `01-topic-source.png` 这类源文件。
7. 每张图检查核心关系、人物身份、主色、媒介、文字和比例。最终 `01-topic.png` 必须是精确 16:9，默认 `1600×900`、白色背景；安全裁切可用 `scripts/finalize_ratio.py`，并用 `scripts/validate_output.py --background white` 验证。透明模式还必须检查 PNG 是否存在 Alpha、边缘是否残留白色描边、整块背景、地面阴影或背景矩形。失败文件不得进入 Markdown。
8. 用户要求“自动插入”“写入 Markdown”或同义表达时，修改前生成一份时间戳备份，再把相对图片路径插在对应段落后。每张图都要有不同的正文锚点，避免相邻堆图或集中放在文末。未要求写入时按文章顺序报告建议位置。

## 模式

### 流程拆解

用于阶段、输入输出、制作链路和服务交付。压缩为 3—5 个节点，使用一条连续 `#D8FF00` 路径连接；可重复同一小生角色，但外观必须一致。

### 核心动作

用于判断、冲突、发现、关键修复和结果。只保留一个小生、一个动作、1—3 个物件和一个可见结果。

### 默认白色背景模式

正文插图默认启用；用户明确要求“透明背景”“抠图”“叠加到网页/文章/卡片”时切换到透明模式，明确要求“黑色背景”“深色背景”时切换到深色模式。

- 提示词默认要求“clean white background, solid white canvas”，白色背景必须干净、均匀，不添加灰色棋盘格或脏纹理。
- 主体内部的白色纸张、卡片、文字和高光可以保留；外部白色画布与主体边界必须清楚。
- 只有透明模式才要求“genuinely transparent background / PNG alpha channel”，并删除整块白底、黑色画布、地面、投影和外部光晕。
- 生成后按所选模式验收：白色模式检查白底均匀和边缘清晰；透明模式确认 RGBA/Alpha 并在棋盘格、深色背景上复查边缘。

## 不可变约束

- 角色必须与参考图和人物规范一致，胸前白色 `小生` 与左胸蓝色闪电保留。
- 若用户提供并确认新头像，将头像作为脸型、发型、护目镜、耳机、服装轮廓和像素媒介的身份真源；正文每张图都必须复用该身份，不得出现“同文不同人”。头像中不可见的细节，才允许沿用既有角色规范，不得自行新增明显配饰。
- `#D8FF00` 是唯一大面积高饱和强调色，蓝色只用于闪电。
- 默认白色模式使用干净白色外部画布；`#0A0A0A`、石墨灰和少量暖白用于主体物件、线条和文字。只有用户明确要求透明或深色时，才切换背景。
- 人物媒介固定为精致像素插画，背景和排版使用咨询报告式高精细编辑视觉。
- 禁止平滑 3D 公仔、黏土、写实真人、日漫重绘、陌生脸、闲鱼黄大色块、蓝紫粉渐变、玻璃拟态、游戏 HUD、PPT、密集仪表盘和随机文字。

## Markdown 安全

- 显式文件路径优先，其次是用户附件或当前明确提到的 Markdown；当前目录只有一个候选时才能自动选择，存在多个候选时询问具体文件。
- 所有最终图片均已保存且可读取后才修改文章；任一图片未落盘时不改 Markdown。
- 备份与原文放在同一目录，命名示例：`文章名.backup-YYYYMMDD-HHMMSS.md`。写入前校验备份内容与原文完全一致。
- 图片使用相对路径，路径相对于文章所在目录计算。
- 不删除原有图片、链接、表格、代码块或 frontmatter。
- 先在同目录临时文件中完成全部插入并校验，再原子替换原文。
- 禁止把图片插进 frontmatter、代码块、表格、HTML 块或列表内部。
- 已存在完全相同的图片引用时不重复插入。
- 修改后重新读取相关段落，确认 Markdown 语法和文件路径都有效。
- 默认只插入通过白底均匀、边缘和尺寸检查的正式 PNG；透明或深色模式按对应背景规则验收。不插入 `*-source.png`。

## 交付

按顺序报告每张图的模式、核心观点、绝对路径、相对路径和插入位置；若已写入文章，同时报告备份和已修改 Markdown 的绝对路径。
